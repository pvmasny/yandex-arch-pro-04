# Задание 7. Проектирование схем коллекций для шардирования данных

## Коллекция orders

```
{
    _id: ObjectId,                          //Уникальный идентификатор заказа;
    custimer_id: ObjectId                   //Идентификатор клиента;
    order_date: date                        //Дату и время оформления заказа;
    items: [                                //Список заказанных товаров и их цену;
        {
            product_id: ObjectId            //Уникальный идентификатор продукта
            product_name: String            //Наименование продукта
            product_category: String        // Категория товара
            quantity: Number,               // Количество в заказе
            price: Decimal128               // Цена за единицу
        }
    ],
    status: String                          //Статус заказа;
    amount: Decimal128                      //Общую сумму заказа;
    geozone: String                         //геозона заказа
}
```
### Шард-ключ
```
{ customer_id: hashed, order_date: 1 }
```

Стратегия шардирования сочетает хешированное распределение по клиенту и диапазонное упорядочивание по дате предоставляет следующие преимущества:
1. Даёт равномерное распределение по шардам;
2. Внутри шарда документы упорядочны по order_date, благодаря этому будет ускорение запросов с фильтрацией по датам.

## Индексы
```
db.orders.createIndex({ _id: 1, status: 1 })
```

## Коллекция carts

```
{
  _id: ObjectId,            //Уникальный идентификатор корзины
  user_id: String,          //Идентификатор пользователя
  session_id: String,       //Идентификатор сессии для гостя

     product_id: String,    // Уникальный идентификатор продукта
     quantity: Number       // Количество в заказе
  ],

  created_at: Date,         // Дату и время создания
  updated_at: Date,         // Дату и время последнего обновления
  expires_at: Date          // Время удаления (TTL) для автоматической очистки старых корзин.
}
```
## Шард-ключ 
```
{ user_id: "hashed", session_id: 1 }
```
Обеспечивает равномерное распределение данных по шардам (нет «горячих» шардов из‑за популярных категорий) с большим числом операций. Позволяет быстро находить гостевую корзину по session_id;
## Индексы
```

db.carts.createIndex({ _id: 1 })
db.carts.createIndex({ session_id: 1, status: 1 })
db.carts.createIndex({ expires_at: 1 }, { expireAfterSeconds: 0 })  // TTL индекс
```

# Задание 8. Выявление и устранение «горячих» шардов

Для мониторинга состояния шардов можно использовать следующие метрики:
* CPU - перегрузка CPU часто коррелирует с «горячим» шардом
* RAM usage (МБ/%) — резкое увеличение может указывать на рост кэша или утечку
* Количество операций чтения/записи - контроль распределения операций по шардам

Так из-за популярной категории товара произошла переггрузка шарда, полагаем что в качестве шард-ключа была выбрана категория. Необходимо пересмотрет шард-ключ, который будет гарантировать равномерное распределение. 

В качестве нового шард-ключа стоит рассмотреть:
```
{ _id: "hashed" }
```
Для смены шард-ключа потребуется полная миграция:
1. Создаем новую коллекцию
```
sh.shardCollection("helloDoc.products_new", { _id: "hashed" })
```
2. Мигируем даные из старой в новую коллекцию
```
mongodump --db helloDoc --collection products --out /backup/
mongorestore --db helloDoc --collection products_new /backup/helloDoc/products.bson
```
3. Проверяем целостность данных
```
db.products.countDocuments()
db.products_new.countDocuments()
```
4. Переименовать коллекцию и удалять старую
```
db.products.renameCollection("products_old")
db.products_new.renameCollection("products")
db.products_old.drop()
```

# Задание 10.2
### Товары
```
CREATE TABLE products (
    category_id UUID,            // Partition key
    product_id UUID,             // Clustering key
    name TEXT,
    price DECIMAL,
    stock MAP<TEXT, INT>,       //geozone: quantity
    color TEXT,
    size TEXT,
    updated_at TIMESTAMP,
    PRIMARY KEY (category_id, product_id)
);
```
Обеспечивает равномерное распределение данных: товары распределяются по партициям на основе категории (электроника, книги и т. п.).Предотвращает «горячие» партиции: даже если в одной категории много товаров, Cassandra равномерно распределит их по узлам.
### Корзины
```
CREATE TABLE carts (
    user_id UUID,              // Partition key 
    session_id UUID,           // Clustering key 
    items LIST<MAP<TEXT, INT>>, // [{'product_id': '...', 'quantity': 2}]
    status TEXT,
    created_at TIMESTAMP,
    updated_at TIMESTAMP,
    expires_at TIMESTAMP,
    PRIMARY KEY (user_id, session_id)
);
```
Все элементы корзины одного пользователя хранятся в одной партиции - быстрые  обновления и чтения в пределах партиции.
Если у одного пользователя сотни/тысячи корзин, вся нагрузка пойдёт на одну партицию.
